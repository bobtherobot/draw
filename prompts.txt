We need to rethink how we're handling text. There are 2 kinds of text objects:
1. single-line text (aka type). Let's rename this to "text-line".
2. text-block (aka area type). let's rename this to "text-block".

Lets stay focused on text-line for now.

Here's the behaviour I'm expecting:

1. create a text-line by selecting the tool, then clicking on the artboard to set the position of the text-line.
2. there should be a horizontal line (aligned to the baseline of the text).
3. there should be a node box on the horizontial line that indicates how the text is aligned. When the text is aligned-left, the box should be on the left. When aligned center, the box should be in the middle of the horizontal line. When aligned right, the box should be on the right.
- once the text-line is placed on the artboard, the horizontal line should default to about 20 pixels wide, once the user starts typing, the horizontal line should resize to match the baseline of the text, so the horizontal line will grow as the user types.
- when the user clicks an empty area on the artboard, or changes tool, this is considered the end of the operation.

- if the user is using the "select" tool or the "direct select" tool, and double clicks on the text, the text-line object will become editable.
- any time the user has the text-line tool selected, they are in text-editing mode, they should be able to simply highlight any text-line text and start editing. This means that when the mouse hovers over a text-line object the cursor will change to a text-select cursor, indicating that they can select the text immediately to edit it. 
- when they are not hovering over an existing text-line, then the asumption is that they want to create a new text-line. Clicking on the artboard will create a new text-line.

... 
text-line objects can be multi-line. The horizontal line should be drawn for all lines in a multiline text-line object. The box (that indicates alignment) only needs to exist on the first line.
